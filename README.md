# Codex Docker

Requires Docker on an x86-64 Linux host. GPU access additionally requires an
NVIDIA driver and NVIDIA Container Toolkit; the launcher enables it when a GPU
is detected.

Build and authenticate from this directory:

```bash
./build-image.sh
./run-codex.sh login
```

Add the launcher to `PATH`, then run it from your project directory:

```bash
mkdir -p "$HOME/.local/bin"
ln -s "$PWD/run-codex.sh" "$HOME/.local/bin/run-codex.sh"
cd /path/to/project
run-codex.sh
```

Use `run-codex.sh bash` for a shell. Additional arguments are passed to the
selected command.

The launcher mounts your project at `/home/codex/workspace` and persistent
credentials and Codex state from `~/.codex-docker/` at `/home/codex/.codex`.
Each container has its own writable home directory, seeded at image build time
with all files from this repository's `home/` directory except `.codex/`.
Files added there, including dotfiles and files not yet tracked by Git, appear
in new containers after rebuilding with `./build-image.sh`. Other home directory
changes are discarded when the container is removed.
It runs as your host user with unrestricted Codex sandbox access inside the
container. Interactive Codex launches use `--no-daemon`, so you can manage
independent instances with tmux.

Tools include Python, PyTorch with CUDA, uv, Lean, Lake, Mathlib,
Comparator, Vampire, CaDiCaL, LaTeX, and OCR. In a container shell:

```bash
python script.py
lean Proof.lean
lean-mathlib.sh ProofWithMathlib.lean
lake build
lake comparator --config config.json
lake check
```

Lean and Mathlib are pinned to v4.35.0. Comparator and the matching `leanexport`
are included in the Lean toolchain; no standalone Comparator installation is
needed. Projects must select Lean v4.35.0 or newer in `lean-toolchain` to use
`lake comparator` and `lake check`, with compatible dependencies.

Run these commands in a project containing `lake-manifest.json` (generated by
`lake update` or a build of trusted project code). Comparator defaults to
`comparator.json`; use `--config` for another filename.

Both commands use Bubblewrap to isolate the project being checked from trusted
files and credentials. The host must permit unprivileged user namespaces, and
Docker security settings must permit Bubblewrap to create its namespaces.
Installing Bubblewrap in the image alone does not guarantee host support. Check
with `run-codex.sh bash -c 'bwrap --ro-bind / / --unshare-user --unshare-pid --unshare-net --proc /proc --dev /dev true'`
and then run a Comparator check in your project.
